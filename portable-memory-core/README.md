# Portable memory core

Node.js 22.13+ with `node:sqlite`; no other packages. Copy this directory as a unit. This installation has a OneBot adapter connected to the bot with automatic first-chat enrollment; automatic enrollment is not proof of a person's informed consent. The core itself remains platform-neutral. Supply an absolute database path, tenant, scope `private:<tenant>` and `scopeKind: 'direct'`. Each core instance permanently binds its tenant/scope. Different private scopes may share a database; group conversations are not supported.

```js
import { createMemoryCore } from './portable-memory-core/core.mjs'
const memory = createMemoryCore({ dbPath: '/absolute/path/memory.sqlite', tenant: 'alice', scope: 'private:alice', scopeKind: 'direct' })
const generation = memory.setAuthorization(true) // privileged consent-management code only
memory.capture({ generation, eventId: 'e1', created: Date.now(), text: 'hello', replies: [{ id: 'r1', text: 'hi', status: 'confirmed' }] })
const events = memory.recall({ generation, limit: 10 })
memory.revokeReply('r1') // deletes whole event; retains event and reply tombstones
memory.setAuthorization(false) // increments generation, deletes and tombstones all events
memory.close()
```

Run `node --test portable-memory-core/core.test.mjs` from the parent directory. To move data, first stop the bot cleanly, then run `node portable-memory-core/backup-memory.mjs <absolute-source-db> <absolute-new-backup-file>`. The destination must not exist. The tool refuses active sessions and SQLite sidecars and verifies the copy under an exclusive SQLite lock. Copy the entire module folder and backup to the destination machine; keep the integration disabled until the database path, host privacy controls and account identities are configured. Authorization, tombstones and unresolved gaps are retained, not silently cleared. The core has been tested on Windows; other operating systems have not yet been tested.

The existing bot can instead be launched explicitly using `node portable-memory-core/start-portable.mjs <absolute-bot-dir> <absolute-existing-memory-db> '*'`. This uses the current Node executable, enables the portable adapter with automatic first-chat enrollment, while keeping withdrawn accounts disabled; it requires a bot entry already wired to this adapter. The launcher is a plain child-process wrapper, not a service manager and not a replacement for Windows Job Object supervision.

## QQ private-chat behavior

An ordinary supported private text conversation automatically enables event memory for a previously unseen account, without an activation message. An account that previously withdrew is not automatically re-enabled. The bot entry does not dispatch memory-management commands from chat; such messages are handled as ordinary conversation. Actual QQ recall notices still remove the affected event from this event-memory database. The library has privileged management APIs but they must not be exposed to chat participants.

The adapter ranks the newest 1000 events plus up to 256 candidates from a bounded scan of the preceding 5000 same-scope events using up to 8 query terms, with capped query/document text and one recent-context slot; it may also include one subsequent captured event within five minutes, labelled as time-nearby rather than an established shared topic. After the selected seed is revalidated, a bounded ±5 minute window may add at most six same-scope events in the same transaction; this is a temporal window, never a claim that the messages form one topic or a complete transcript. Output is capped at 800 bytes and marks an incomplete reference. It revalidates selected events immediately before exposing a reference, but cannot retract information already supplied to a model or already sent. Output cleanup is best effort, not a semantic confidentiality guarantee. It is not semantic recall or a global identity store. Older events and truncated text may be missed. The migration helper is restricted to the old pilot schema; it cannot establish either bot account's identity, so an operator must independently verify the actual bot and each message before an offline import. The helper refuses non-first authorization generations and conflicts, and retains tombstones.

## Experimental self-report index

Newly confirmed private text events are also considered for a deliberately narrow literal preference index: only the exact patterns in `claims.mjs` and its closed vocabulary are accepted. A preference is an attributed historical self-report, not a verified fact or proof of current preference. A matching question may retrieve up to two older indexed statements alongside recent context; v1 literal rows and carefully paired v2 compositions are read together with one deduplicated signature, and v2 rows are never deleted by a rollback. Contradictions, negation, new evidence, omitted statements and outdated information remain possible. The final adapter read verifies selected evidence and the current bounded claim signature in one transaction; other callers of `recallRelevant` must call `revalidateRelevant` with the query and returned signature. An empty reference does not convey the incomplete marker. Existing and imported events are not backfilled; this is not semantic memory or complete fact extraction. The claim row is written in the same transaction as its source event and is deleted with the event through its foreign key, including reply recall, authorization withdrawal and offline gap reset. It does not remove prior derived text from other memory systems, logs, backups, SQLite pages or model providers.

## Security and limits

The host must authenticate the user, choose the correct tenant/scope, guard `setAuthorization` and revoke methods, and secure database files and backups. This library cannot prevent a caller with direct file or management access from bypassing those controls. The privacy filter is mandatory but heuristic and cannot guarantee detection of all sensitive information. A stale generation is rejected inside the same write transaction as capture. Calls that encounter errors are not retried; duplicate IDs are errors, never successful replays. A captured event needs 1–20 already-confirmed replies; completeness is verified on recall, which returns at most 50 whole events. Deleting a reply removes its whole event. Tombstones persist indefinitely; storage encryption, retention expiry, migrations for pre-existing conflicting schemas, concurrency stress/crash testing and secure deletion of SQLite pages or backups are out of scope. The caller must not pass group scopes disguised as direct scopes. Filter code must be shipped together with the core.
